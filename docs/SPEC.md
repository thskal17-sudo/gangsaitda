# 강사잇다 기획서

작성 중인 문서입니다. **확정된 것만** 적고, 아직 정하지 않은 것은 `미정`으로 남겨둡니다.
`CLAUDE.md`와 이 문서가 어긋날 때는 **이 문서가 기준**입니다.

---

## 1. 메뉴 구조 (강사 화면)

하단 탭 **2개**로 시작합니다.

| 탭 | 주소 | 이 탭에서 하는 일 | 현재 상태 |
|---|---|---|---|
| 홈 | `/` | 미정 | 빈 화면 |
| 공고 | `/jobs` | 지원할 수 있는 공고 목록 보기 | 목록 완성 (샘플 데이터) |

### 정해진 것

- **휴대폰**에서는 메뉴가 화면 **아래에 고정**된 탭이고, 어느 화면에서든 항상 보입니다.
- **PC·태블릿**(가로 768px 이상)에서는 하단 탭 대신 **위쪽 띠 오른쪽**에 메뉴가 있습니다.
- 지금 보고 있는 탭은 **연보라 알약 배경 + 진한 보라 아이콘 + 굵은 글씨**로 표시하고,
  나머지는 배경 없이 회색으로 둡니다. 색 하나에만 기대지 않아 구분이 쉽습니다.
  PC의 위쪽 메뉴도 같은 방식입니다.
- 화면 위쪽 띠 왼쪽에는 서비스 이름(`강사잇다`)이 있고, 누르면 홈으로 갑니다.

### 아직 정하지 않은 것

- 홈 화면에 무엇을 보여줄지
- 공고 필터·검색
- 로그인·로그아웃 버튼을 둘 자리 (회원가입·로그인 화면을 만들 때 정함)
- 탭을 더 늘릴지 (예: 지원현황, 스크랩, MY)

> 탭 개수는 **2개로 시작**합니다. (`CLAUDE.md`도 이 문서를 따르도록 고쳐두었습니다.)
> 탭을 늘리기로 하면 `components/nav-tabs.tsx`의 `TABS` 목록에 한 줄씩 추가하면 됩니다.
> 휴대폰 하단 탭과 PC 위쪽 메뉴에 함께 반영됩니다.

## 2. 공고 화면 (`/jobs`)

### 다루는 수업

방과후·평생교육·기업강의 등 **여러 종류를 함께** 다룹니다.
그래서 카드에는 어느 수업이든 공통으로 있는 정보만 넣습니다.

### 공고 카드에 보이는 것

| 위치 | 내용 | 예시 |
|---|---|---|
| 위 왼쪽 | 기관명 | 새솔초등학교 |
| 위 오른쪽 | 남은 날짜 배지 | `D-9` |
| 가운데 | 공고 제목 (길면 두 줄까지) | 방과후 코딩(스크래치) 강사 모집 |
| 아래 | 지역 · 마감일 | 서울 마포구 · 9월 25일(금) 마감 |

강사료·수업 시간은 카드에 넣지 않습니다. 공고를 눌렀을 때(상세 화면, 아직 안 만듦) 보여줍니다.

### 남은 날짜 배지

| 남은 날 | 표시 | 색 |
|---|---|---|
| 당일 | 오늘 마감 | 주황 배경 |
| 1~3일 | 마감임박 D-2 | 주황 배경 |
| 4일 이상 | D-9 | 회색 테두리 |

'3일'은 `components/job-card.tsx`의 `URGENT_DAYS` 한 곳에서 바꿀 수 있습니다.

### 목록 규칙

- **마감이 가까운 순**으로 보여줍니다.
- 카드는 휴대폰에서 한 줄에 1개, 태블릿(768px 이상)에서 2개, PC(1024px 이상)에서 3개씩 놓습니다.
  한 줄에 놓인 카드끼리는 높이를 맞추고, 지역·마감 줄은 항상 카드 맨 아래에 둡니다.
- 마감이 지난 공고는 목록에 **보이지 않습니다**.
- 날짜는 서버가 어디에 있든 **한국 시간 기준**으로 계산합니다.
- 화면 맨 위에 "지원할 수 있는 공고 N건"으로 개수를 보여줍니다. 0건이면 안내 문구가 나옵니다.

### 공고 등록

- 운영자가 데이터베이스(Supabase) 관리 화면에서 **직접 입력**합니다. 엑셀처럼 칸을 채우는 방식이라,
  사이트 안에 공고 등록 화면은 만들지 않습니다.
- 기관이 직접 올리는 기능(기관 콘솔)은 MVP 이후입니다.

### 지원 방법

- 강사는 **공고에 적힌 방법**(이메일·전화·지원서 링크)으로 기관에 직접 지원합니다. 상세 화면에서 보여줍니다.
- 지원 방법을 포함한 상세 내용은 **회원만** 볼 수 있습니다. (아래 '4. 회원' 참고)
- 강사잇다 안에서 지원하는 기능(강사 프로필·지원 내역)은 나중에 정합니다.

### 지금 상태

- 데이터베이스가 아직 없어서 **샘플 공고 5개**를 씁니다. 화면에도 "샘플입니다"라고 적어두었습니다.
- Supabase를 붙이면 `lib/jobs.ts`의 `getOpenJobs` 안쪽만 바꾸면 됩니다. 화면 코드는 그대로 둡니다.
- 카드를 누르면 공고 상세 화면으로 갑니다.

## 3. 공고 상세 화면 (`/jobs/공고번호`)

### 누가 무엇을 보나

| 항목 | 비회원 | 회원 |
|---|---|---|
| 기관 · 제목 · 남은 날짜 배지 | 보임 | 보임 |
| 지역 · 마감일 | 보임 | 보임 |
| 강사료 · 수업 일정 · 수업 대상 · 모집 인원 | — | 보임 |
| 상세 내용 · 지원 자격 | — | 보임 |
| 지원 방법 (제출 서류, 지원 버튼) | — | 보임 |

- 비회원에게는 가려진 자리에 **"무료 회원가입하고 자세히 보기"** 버튼과 로그인 링크를 보여줍니다.
  가입·로그인을 마치면 보던 공고로 돌아옵니다.
- 가려진 내용은 화면에서 숨기는 게 아니라 **서버에서부터 보내지 않습니다.**
  브라우저 개발자 도구로 들여다봐도 볼 수 없습니다.

### 항목

- 강사료·수업 일정·수업 대상·지원 자격·제출 서류는 공고마다 형식이 달라서 운영자가 **글로 자유롭게** 적습니다.
  지원 자격은 한 줄에 하나씩 적으면 점 목록으로 보입니다.
- **꼭 적어야 하는 것**: 강사료, 수업 일정, 상세 내용, 지원 방법(하나 이상).
  나머지는 비어 있으면 화면에 나오지 않습니다.

### 지원 버튼

- 지원서 링크 → 이메일 → 전화 순서로 놓고, 맨 앞의 버튼을 보라색으로 강조합니다.
- 이메일은 제목(`[강사잇다] 공고 제목 지원`)이 자동으로 들어갑니다.
- 버튼 아래에 이메일 주소·전화번호를 글자로도 적어 둡니다. PC에 메일 프로그램이 없을 때 복사해 쓸 수 있게 하려는 것입니다.
- 지원서 링크는 새 창으로 열립니다. `http`·`https`로 시작하는 주소만 링크로 만듭니다.

### 그 밖

- **마감이 지난 공고**: 목록에는 나오지 않습니다. 주소로 직접 들어오면 '마감' 배지와 "마감된 공고입니다"를 보여주고, 지원 버튼은 숨깁니다.
- **없는 공고 주소**: "공고를 찾을 수 없습니다"와 목록으로 가는 버튼을 보여줍니다.
- **배치**: 휴대폰은 요약(지원 버튼 포함) → 상세 내용 → 지원 자격 순서로 한 줄입니다.
  PC는 왼쪽에 본문, 오른쪽에 요약을 두고, 요약은 스크롤해도 따라옵니다.

## 4. 회원

- 공고 **목록은 누구나**, 공고 **상세는 회원만** 봅니다. 가입은 무료이고, 가입하면 모두 **무료회원**입니다.
- **가입 항목**: 이름, 연락처, 이메일, 비밀번호. 그리고 **개인정보 수집·이용 동의(필수)** 를 받습니다
  (개인정보보호법상 이름·연락처·이메일을 받으려면 동의가 필요합니다).
- **로그인**: 이메일 + 비밀번호.
- **회원 등급**: 등급을 적는 칸을 만들어 두고, 지금은 모두 '무료'입니다.
  유료회원·결제는 MVP 이후입니다 (구조만 열어두고 만들지 않음).
- **이메일 인증**: 메일 발송 설정을 하기 전까지는 **끄고** 운영합니다. 가입하면 바로 이용할 수 있습니다.
  그래서 '비밀번호 찾기'는 메일 설정을 마친 뒤에 붙입니다.
  그 전까지 비밀번호를 잊은 회원은 운영자가 Supabase 관리 화면에서 처리합니다.
- 연락처·이메일은 **서비스 운영 목적으로만** 씁니다. 공고 알림이나 홍보 메시지를 보내려면
  별도 동의(광고성 정보 수신 동의)를 따로 받아야 합니다.

### 준비할 것 (Supabase)

- Supabase 프로젝트 `gangsaitda`, 지역 Seoul. **Authentication → Email → Confirm email 끔.**
- 작업 공간 설정
  - Network access: `*.supabase.co` 허용
  - 환경변수: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
  - `secret`·`service_role` 키와 데이터베이스 비밀번호는 넣지 않습니다.

### 만들 때 지킬 것 (다음 단계 메모)

- 회원 정보: 이름·연락처·이메일·등급(기본 '무료')·동의한 시각을 저장합니다.
  회원은 **자기 정보만** 읽을 수 있고, 등급은 스스로 바꿀 수 없게 막습니다.
- 공고 상세 내용은 요약과 **따로 저장**하고, 회원만 읽을 수 있게 데이터베이스에서 막습니다.
  비회원이 데이터베이스 주소로 직접 요청해도 상세 내용을 가져갈 수 없어야 합니다.
- 화면 코드는 그대로 두고, `lib/member.ts`의 `getCurrentMember`와 `lib/jobs.ts`의 함수 안쪽만 바꿉니다.

## 5. 화면 크기 기준

강사 화면은 **휴대폰이 먼저**입니다. PC에서도 넓게 볼 수 있게 두 가지 모양을 씁니다.

| 화면 폭 | 기준 | 메뉴 | 본문 폭 |
|---|---|---|---|
| 768px 미만 (휴대폰) | **390px** 기준으로 설계 | 하단 탭 | 최대 430px, 가운데 |
| 768px 이상 (태블릿·PC) | 넓은 화면에 맞게 배치 | 위쪽 띠 오른쪽 | 최대 1080px, 가운데 |

- 새 화면을 만들 때는 휴대폰 모양을 먼저 만들고, 그다음 PC 모양을 맞춥니다.
- 기관 콘솔(데스크톱)은 지금 만들지 않습니다.

## 6. 홈페이지와 앱

- **웹사이트로 만듭니다.** 설치하는 앱이 아니라 인터넷 주소로 여는 사이트이고,
  PC에서는 위쪽 메뉴·넓은 화면, 휴대폰에서는 아래쪽 메뉴로 화면 크기에 맞춰 모양이 바뀝니다 (지금 모양 유지).
- **홈페이지**: 강사잇다는 자기 저장소(`gangsaitda`)에서 **별도 홈페이지**로 운영합니다.
  Vercel에 올려 인터넷 주소를 만들고, GitHub 본 줄기(`main`)의 내용이 올라갑니다.
- **배포 시점**: 아래 목록을 갖춘 뒤에 공개합니다. 순서대로, 한 번에 화면 하나씩 만듭니다.

  | 순서 | 할 일 | 상태 |
  |---|---|---|
  | 1 | 공고 상세 화면 (회원 전용) | 완료 (샘플 데이터) |
  | 2 | 회원가입·로그인 | 화면 완성 (Supabase 표 만들기·실제 가입 확인 남음) |
  | 3 | 진짜 공고 데이터 (Supabase) | 예정 |
  | 4 | 홈 화면 | 예정 |
  | 5 | 공개 전 마무리: 사이트 아이콘, 링크 미리보기, 없는 주소 안내 화면, 개인정보처리방침·회원 탈퇴 방법 | 예정 |
- **회사 홈페이지와의 관계**: 한국엑스퍼트교육원 회사 홈페이지(링크허브, `rinktree` 저장소)와는
  **따로 운영**합니다. 색·디자인과 역할이 달라서입니다. 회사 홈페이지의 "강사잇다" 버튼(`/recruit`)은
  나중에 이 홈페이지 주소로 연결합니다 (회사 홈페이지 쪽 작업, 아직 안 함).
- **앱**: 나중에 정합니다. 후보는 ① 휴대폰 홈 화면에 설치하는 웹앱, ② 앱스토어 등록입니다.
  네이티브 앱(휴대폰 전용으로 따로 개발)은 만들지 않습니다.
