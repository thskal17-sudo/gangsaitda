작성 중인 문서입니다. **확정된 것만** 적고, 아직 정하지 않은 것은 `미정`으로 남겨둡니다.
`CLAUDE.md`와 이 문서가 어긋날 때는 **이 문서가 기준**입니다.

## 1. 메뉴 구조 (강사 화면)

하단 탭 **5개**입니다.

| 탭 | 주소 | 이 탭에서 하는 일 | 현재 상태 |
|---|---|---|---|
| 홈 | `/` | 첫인사 · 오늘 올라온 공고 수 · 마감이 가까운 공고 5개 · 바로가기 (아래 '1-1. 홈') | 완성 |
| 공고 | `/jobs` | 지원할 수 있는 공고 목록 보기 | 목록 완성 (Supabase) |
| 자격증 | `/certificates` | 한국엑스퍼트교육원의 **자격증 과정 안내·신청** | 준비 중 화면 |
| 강사섭외 | `/request` | 학교·기관이 **강사섭외 의뢰서**를 남기면 운영자가 받아 공고로 올림 (받은 의뢰는 Supabase 표에 쌓임) | 의뢰서 완성 |
| 회원가입 / 로그아웃 | `/signup` | 비회원에게는 **회원가입**, 회원에게는 **로그아웃**(누르면 보던 화면에 머묾) | 완성 |

### 정해진 것

- **휴대폰**에서는 메뉴가 화면 **아래에 고정**된 탭이고, 어느 화면에서든 항상 보입니다.
- **PC·태블릿**(가로 768px 이상)에서는 하단 탭 대신 **위쪽 띠 오른쪽**에 메뉴가 있습니다.
- 지금 보고 있는 탭은 **연파랑 알약 배경 + 파란 아이콘 + 굵은 글씨**로 표시하고,
  나머지는 배경 없이 회색으로 둡니다. 색 하나에만 기대지 않아 구분이 쉽습니다.
  PC의 위쪽 메뉴도 같은 방식입니다.
- 화면 위쪽 띠 왼쪽에는 서비스 **로고**(`강사잇다` 그림, 남색 + "잇"만 빨강)이 있고, 누르면 홈으로 갑니다.
- 위쪽 띠 **오른쪽 끝**에 **로그인** 버튼이 있습니다 (비회원에게만, 휴대폰·PC 모두). 로그인 뒤 보던 화면으로 돌아옵니다.
  회원의 **로그아웃**은 메뉴 마지막 칸에 있습니다. 가입·로그인·계정 찾기 화면에서는 로그인 버튼을 숨깁니다.

### 1-1. 홈 (`/`)

위에서 아래로:
1. **첫인사**: 제목 "강사와 기관을 잇다", 설명 "부산·울산·경남 학교·기관의 강사 공고를 한곳에서 확인하세요."
   버튼 [공고 보기] + 비회원에게만 [무료 회원가입]
2. **오늘 올라온 공고 N건**: 한국 날짜로 오늘 등록된 공고 중 마감 전인 것의 개수 (`supabase/today-job-count.sql`, 개수만 알려줌).
   누르면 공고 탭이 **오늘 올라온 공고만** 모아서 보여줍니다 (`/jobs?view=today`, `supabase/today-job-titles.sql`). 세는 기준은 같습니다.
3. **마감이 가까운 공고 5개** + [전체 보기 →]. 공고 탭과 같은 규칙 (비회원은 제목만). 개수는 `app/page.tsx`의 `DEADLINE_SOON_COUNT`
4. **바로가기**: 자격증 과정, 강사가 필요하신가요?(강사섭외)

### 아직 정하지 않은 것

- 공고 필터·검색
- 자격증 화면에 무엇을 어떤 모양으로 보여줄지 (과정 목록, 신청 방법)

> 탭은 `components/nav-tabs.tsx`의 `TABS` 목록(앞 4칸)과 마지막 칸(회원가입/로그아웃)으로 되어 있습니다.
> 휴대폰 하단 탭과 PC 위쪽 메뉴에 함께 반영됩니다.

## 2. 공고 화면 (`/jobs`)

### 다루는 수업

방과후·평생교육·기업강의 등 **여러 종류를 함께** 다룹니다.
그래서 카드에는 어느 수업이든 공통으로 있는 정보만 넣습니다.

### 공고 카드에 보이는 것

| 위치 | 내용 | 예시 | 비회원 |
|---|---|---|---|
| 위 왼쪽 | 기관명 | 새솔초등학교 | 안 보임 |
| 위 오른쪽 | 남은 날짜 배지 | `D-9` | 안 보임 |
| 가운데 | 공고 제목 (길면 두 줄까지) | 방과후 코딩(스크래치) 강사 모집 | **보임** |
| 아래 | 지역 · 마감일 | 서울 마포구 · 9월 25일(금) 마감 | 안 보임 |

- 비회원 카드에는 제목과 "🔒 기관·지역·마감일은 회원만 볼 수 있어요" 한 줄만 나옵니다.
- 수업 일정은 카드에 넣지 않습니다. 공고를 눌렀을 때 상세 화면에서 보여줍니다.

### 남은 날짜 배지

| 남은 날 | 표시 | 색 |
|---|---|---|
| 당일 | 오늘 마감 | 주황 배경 |
| 1~3일 | 마감임박 D-2 | 주황 배경 |
| 4일 이상 | D-9 | 회색 테두리 |

'3일'은 `components/job-card.tsx`의 `URGENT_DAYS` 한 곳에서 바꿀 수 있습니다.

### 목록 규칙

- **마감이 가까운 순**으로 보여줍니다.
- 카드는 휴대폰에서 한 줄에 1개, 태블릿(768px 이상)에서 2개, PC(1024px 이상)에서 3개씩 놓습니다.
  한 줄에 놓인 카드끼리는 높이를 맞추고, 지역·마감 줄은 항상 카드 맨 아래에 둡니다.
- 마감이 지난 공고는 목록에 **보이지 않습니다**.
- 날짜는 서버가 어디에 있든 **한국 시간 기준**으로 계산합니다.
- 화면 맨 위에 "지원할 수 있는 공고 N건"으로 개수를 보여줍니다. 0건이면 안내 문구가 나옵니다.

### 공고 등록

- 지금은 운영자가 데이터베이스(Supabase) 관리 화면(Table Editor)에서 **직접 입력**합니다.
  사이트 안의 관리자 화면(`/admin`, 4-3 참고)에 등록 화면을 차례로 붙입니다.
- 공고는 **표 두 개**에 나눠 적습니다 (`supabase/jobs.sql`).
  1. `jobs` 표에 **제목**을 적으면 공고 번호(`id`)가 저절로 생깁니다.
  2. `job_details` 표에 그 번호(`job_id`)와 나머지(기관·지역·마감일·원문 링크·수업 일정·지원 방법 …)를 적습니다.
  - 2까지 적어야 사이트에 나옵니다. 제목만 적힌 공고는 보이지 않습니다.
  - 제목은 비회원에게도 보이므로 **날짜·기간을 넣지 않습니다**. 예) `(2026.9.23.~10.1., 5일간)`은 빼고, 기간은 수업 일정 칸에 적습니다.
  - 꼭 적어야 하는 칸(기관·지역·마감일·수업 일정·상세 내용)을 비우면 저장이 거절됩니다.
- 기관이 직접 올리는 기능(기관 콘솔)은 MVP 이후입니다.

### 지원 방법

- 강사는 **공고에 적힌 방법**(이메일·지원서 링크)으로 기관에 직접 지원합니다. 상세 화면에서 보여줍니다.
- 지원 방법을 포함한 상세 내용은 **회원만** 볼 수 있습니다. (아래 '4. 회원' 참고)
- 강사잇다 안에서 지원하는 기능(강사 프로필·지원 내역)은 나중에 정합니다.

### 지금 상태

- 공고는 Supabase에서 읽습니다. 샘플은 지웠고, **비어 있는 상태로 시작**해 운영자가 진짜 공고를 넣습니다.
- 카드를 누르면 공고 상세 화면으로 갑니다.

## 3. 공고 상세 화면 (`/jobs/공고번호`)

### 누가 무엇을 보나

| 항목 | 비회원 | 회원 |
|---|---|---|
| 제목 | 보임 | 보임 |
| 기관 · 남은 날짜 배지 · 지역 · 마감일 | — | 보임 |
| 원문 공고 링크 ("원문 공고 보기 ↗", 새 창) | — | 보임 |
| 수업 일정 · 수업 대상 · 모집 인원 | — | 보임 |
| 상세 내용 · 지원 자격 | — | 보임 |
| 지원 방법 (제출 서류, 지원 버튼) | — | 보임 |

- 비회원에게는 가려진 자리에 **"무료 회원가입하고 자세히 보기"** 버튼과 로그인 링크를 보여줍니다.
  가입·로그인을 마치면 보던 공고로 돌아옵니다.
- 가려진 내용은 화면에서 숨기는 게 아니라 **서버에서부터 보내지 않습니다.**
  브라우저 개발자 도구로 들여다봐도 볼 수 없습니다.

### 항목

- 수업 일정·수업 대상·지원 자격·제출 서류는 공고마다 형식이 달라서 운영자가 **글로 자유롭게** 적습니다.
  지원 자격은 한 줄에 하나씩 적으면 점 목록으로 보입니다.
- **꼭 적어야 하는 것**: 수업 일정, 상세 내용.
- 지원 방법(지원서 링크·이메일)은 비워도 됩니다. 방문·우편 접수만 받는 공고는 "지원 방법은 원문 공고에서 확인해 주세요"로 안내합니다.
- **강사료와 전화 문의는 받지 않습니다** (보여주지 않음).
  나머지는 비어 있으면 화면에 나오지 않습니다.

### 지원 버튼

- 지원서 링크 → 이메일 순서로 놓고, 맨 앞의 버튼을 파란색으로 강조합니다.
- 이메일은 제목(`[강사잇다] 공고 제목 지원`)이 자동으로 들어갑니다.
- 버튼 아래에 이메일 주소를 글자로도 적어 둡니다. PC에 메일 프로그램이 없을 때 복사해 쓸 수 있게 하려는 것입니다.
- 지원서 링크는 새 창으로 열립니다. `http`·`https`로 시작하는 주소만 링크로 만듭니다.

### 그 밖

- **마감이 지난 공고**: 목록에는 나오지 않습니다. 회원이 주소로 직접 들어오면 '마감' 배지와 "마감된 공고입니다"를 보여주고, 지원 버튼은 숨깁니다.
  비회원에게는 마감 여부도 알리지 않고 제목과 회원 안내만 보여줍니다.
- **없는 공고 주소**: "공고를 찾을 수 없어요"와 [공고 목록 보기] [홈으로] 버튼을 보여줍니다.
- **없는 주소 전체**: "페이지를 찾을 수 없어요"와 [홈으로] [공고 보기] 버튼 (`app/not-found.tsx`).
- **배치**: 휴대폰은 요약(지원 버튼 포함) → 상세 내용 → 지원 자격 순서로 한 줄입니다.
  PC는 왼쪽에 본문, 오른쪽에 요약을 두고, 요약은 스크롤해도 따라옵니다.

## 4. 회원

- 공고 **목록은 누구나**, 공고 **상세는 회원만** 봅니다. 가입은 무료이고, 가입하면 모두 **무료회원**입니다.
- **가입 항목**: 이름, 연락처, 이메일, 비밀번호. 그리고 **개인정보 수집·이용 동의(필수)** 를 받습니다
  (개인정보보호법상 이름·연락처·이메일을 받으려면 동의가 필요합니다).
- **로그인**: 이메일 + 비밀번호.
- **회원 등급**: 등급을 적는 칸을 만들어 두고, 지금은 모두 '무료'입니다.
  유료회원·결제는 MVP 이후입니다 (구조만 열어두고 만들지 않음).
- **이메일 인증**: 메일 발송 설정을 하기 전까지는 **끄고** 운영합니다. 가입하면 바로 이용할 수 있습니다.
- **이메일(아이디) 찾기** (`/find-email`): 이름·연락처를 넣으면 가입한 이메일을 **일부 가려서** 보여줍니다 (예: `ab***@naver.com`).
  가리는 일은 데이터베이스 함수(`supabase/find-email.sql`)가 해서 전체 이메일은 밖으로 나가지 않습니다.
- **비밀번호 찾기** (`/find-password`): 메일로 다시 정하는 기능은 **도메인을 산 뒤** 메일 발송 설정과 함께 붙입니다.
  그 전까지는 "운영자에게 문의" 안내를 보여주고, 운영자가 본인 확인 뒤 `supabase/admin-reset-password.sql`로 임시 비밀번호를 정해 줍니다.
  문의처는 `lib/site.ts`의 `SUPPORT_CONTACT` 한 곳에서 바꿉니다.
- 로그인 화면 아래에 **이메일 찾기 · 비밀번호 찾기** 링크가 있습니다.
- **개인정보 수집·이용 동의 문구** (가입 화면에서 펼쳐 볼 수 있음, 확정):
  수집 항목 이름·연락처·이메일 / 이용 목적 회원 확인, 공고 상세 정보 제공, 서비스 이용 관련 안내 및 문의 응대 /
  보관 기간 회원 탈퇴 시까지 (법령에 따라 보관해야 하는 경우 그 기간까지) / 동의를 거부하면 가입할 수 없음.
- 연락처·이메일은 **서비스 운영 목적으로만** 씁니다. 공고 알림이나 홍보 메시지를 보내려면
  별도 동의(광고성 정보 수신 동의)를 따로 받아야 합니다.

### 준비할 것 (Supabase)

- Supabase 프로젝트 `gangsaitda`, 지역 Seoul. **Authentication → Email → Confirm email 끔.**
- 회원 정보 표: `supabase/members.sql`을 SQL Editor에서 실행 (**완료**).
- **SQL 실행 규칙**: 저장소의 SQL 파일은 끝에 `notify pgrst, 'reload schema';`가 들어 있습니다.
  새 표·함수를 만든 뒤 사이트에서 `PGRST205 … schema cache` 같은 오류가 나면, SQL Editor에서 이 한 줄만 다시 실행합니다.
  그래도 안 되면 Table Editor에 그 표가 실제로 있는지 확인합니다 (SQL이 실행되지 않았을 수 있음).
- Vercel 배포 (**완료**): GitHub 저장소 연결, 환경변수 두 개(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`) 입력.
  main 에 합치면 자동으로 다시 올라가고, PR 마다 미리보기 주소가 생깁니다.
  환경변수를 바꾸면 Deployments → Redeploy 를 해야 반영됩니다.
- 나중에 도메인을 사면 Vercel Settings → Domains 에서 연결합니다. 메일 기능을 붙일 때
  Supabase Authentication → URL Configuration 에 그 주소를 적습니다.
- 작업 공간 설정
  - Network access: `*.supabase.co` 허용
  - 환경변수: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
  - `secret`·`service_role` 키와 데이터베이스 비밀번호는 넣지 않습니다.

### 만들 때 지킬 것 (다음 단계 메모)

- 회원 정보: 이름·연락처·이메일·등급(기본 '무료')·동의한 시각을 저장합니다.
  회원은 **자기 정보만** 읽을 수 있고, 등급은 스스로 바꿀 수 없게 막습니다.
- 공고는 제목(`jobs`)과 나머지(`job_details`)를 **따로 저장**하고, 두 표 모두 회원만 직접 읽을 수 있게 데이터베이스에서 막습니다 (**완료**).
  비회원은 데이터베이스 함수로 '번호·제목'만 받습니다. 비회원이 데이터베이스 주소로 직접 요청해도 제목 말고는 가져갈 수 없습니다.

## 4-1. 강사섭외 (`/request`)

- 학교·기관 담당자가 **로그인 없이** 의뢰서를 보냅니다. 보내면 "의뢰가 접수되었습니다" 화면이 나옵니다.
- **받는 항목**

  | 항목 | 필수 |
  |---|---|
  | 기관명, 기관 종류(학교·공공기관·기업·복지관·센터·기타), 지역 | 필수 |
  | 담당자 이름, 연락처, 이메일 | 필수 |
  | 필요한 분야·과목, 희망 일정 | 필수 |
  | 수업 대상, 필요한 강사 수, 예산·강사료, 요청 사항 | 선택 |
  | 개인정보 수집·이용 동의 | 필수 |

- **개인정보 동의 문구**: 수집 항목 담당자 이름·연락처·이메일 / 이용 목적 강사 섭외 의뢰 확인 및 진행 상황 연락 /
  보관 기간 **의뢰 처리 완료 후 1년까지** / 거부하면 의뢰를 접수할 수 없음.
- **저장**: Supabase `instructor_requests` 표 (`supabase/instructor-requests.sql`). 사이트에서는 **보내기만** 되고,
  보낸 사람을 포함해 아무도 사이트에서 읽을 수 없습니다. 운영자는 Table Editor에서 보고, `status`를 접수 → 처리 중 → 완료로 바꿉니다.
- 처리 완료 후 1년이 지난 의뢰는 운영자가 지웁니다 (개인정보 보관 기간).
- 새 의뢰가 왔다고 **알려주는 기능(카톡·메일)은 MVP 이후**입니다. 그 전까지 운영자가 표를 직접 확인합니다.
- 자동 광고 글을 막기 위해 사람에게는 안 보이는 칸을 하나 두고, 그 칸이 채워진 글은 저장하지 않습니다.

## 4-3. 관리자 화면 (`/admin`)

- 운영자 전용. 따로 배포하거나 도메인을 사지 않고, 같은 사이트의 `/admin` 주소에 둡니다. 메뉴·탭에는 나오지 않습니다.
- **누가 들어오나**: 데이터베이스의 관리자 명단(`supabase/admins.sql`)에 있는 회원만.
  - 로그인 안 함 → 로그인 화면으로 보냄 (로그인하면 다시 `/admin`으로)
  - 일반 회원 → "관리자만 볼 수 있어요" 안내
  - 명단은 SQL Editor 에서만 고칩니다 (`supabase/admin-add.sql`). 사이트에서는 아무도 명단을 읽거나 고칠 수 없습니다.
  - 검색엔진에 나오지 않게 합니다.
- 만드는 순서 (한 번에 하나씩)
  1. **공고 관리** — 마감된 것까지 모든 공고 목록. 숫자 요약(전체·모집 중·오늘 올린 공고·3일 안에 마감), 제목·기관·지역 검색, 걸러 보기(전체·모집 중·오늘 올린 공고·마감). 상세를 아직 안 넣은 공고는 "상세 없음"으로 표시. ✅
  2. 공고 등록·수정·내리기
  3. 강사섭외 의뢰 보기·처리 상태 바꾸기
  4. 엑셀로 여러 공고 한꺼번에 올리기
  5. 회원 목록
- 아직 만들지 않은 메뉴는 "준비 중"으로 보여주고 누를 수 없습니다.

## 5. 화면 크기 기준

> 디자인은 **토스 스타일**을 참고합니다 (파랑 강조색, Pretendard 글꼴, 테두리 없는 흰 카드). 색·글꼴 값은 `CLAUDE.md`의 디자인 토큰을 따릅니다.

강사 화면은 **휴대폰이 먼저**입니다. PC에서도 넓게 볼 수 있게 두 가지 모양을 씁니다.

| 화면 폭 | 기준 | 메뉴 | 본문 폭 |
|---|---|---|---|
| 768px 미만 (휴대폰) | **390px** 기준으로 설계 | 하단 탭 | 최대 430px, 가운데 |
| 768px 이상 (태블릿·PC) | 넓은 화면에 맞게 배치 | 위쪽 띠 오른쪽 | 최대 1080px, 가운데 |

- 새 화면을 만들 때는 휴대폰 모양을 먼저 만들고, 그다음 PC 모양을 맞춥니다.
- 기관 콘솔(데스크톱)은 지금 만들지 않습니다.

## 6. 홈페이지와 앱

- **웹사이트로 만듭니다.** 설치하는 앱이 아니라 인터넷 주소로 여는 사이트이고,
  PC에서는 위쪽 메뉴·넓은 화면, 휴대폰에서는 아래쪽 메뉴로 화면 크기에 맞춰 모양이 바뀝니다 (지금 모양 유지).
- **홈페이지**: 강사잇다는 자기 저장소(`gangsaitda`)에서 **별도 홈페이지**로 운영합니다.
  Vercel에 올려 인터넷 주소를 만들고, GitHub 본 줄기(`main`)의 내용이 올라갑니다.
- **배포 시점**: 아래 목록을 갖춘 뒤에 공개합니다. 순서대로, 한 번에 화면 하나씩 만듭니다.

  | 순서 | 할 일 | 상태 |
  |---|---|---|
  | 1 | 공고 상세 화면 (회원 전용) | 완료 |
  | 2 | 회원가입·로그인 | 완료 (실제 가입·로그인·로그아웃, members 표 확인함) |
  | 3 | 진짜 공고 데이터 (Supabase) | 화면 완성 (공고 표 만들기·실제 확인 남음) |
  | 4 | 홈 화면 | 예정 |
  | 5 | 공개 전 마무리: ~~사이트 아이콘, 링크 미리보기, 없는 주소 안내 화면~~(완료), 개인정보처리방침·회원 탈퇴 방법 | 진행 중 |
  | 6 | 도메인 구입 → Vercel 연결 → 메일 발송 설정(보내는 주소도 도메인으로) → **비밀번호 재설정(메일)** → Supabase 주소 설정 | 예정 (공개 전 필수) |
- **회사 홈페이지와의 관계**: 한국엑스퍼트교육원 회사 홈페이지(링크허브, `rinktree` 저장소)와는
  **따로 운영**합니다. 색·디자인과 역할이 달라서입니다. 회사 홈페이지의 "강사잇다" 버튼(`/recruit`)은
  나중에 이 홈페이지 주소로 연결합니다 (회사 홈페이지 쪽 작업, 아직 안 함).
- **앱**: 나중에 정합니다. 후보는 ① 휴대폰 홈 화면에 설치하는 웹앱, ② 앱스토어 등록입니다.
  네이티브 앱(휴대폰 전용으로 따로 개발)은 만들지 않습니다.
